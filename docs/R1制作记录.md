## 当前内容

`scenes/west_coast_r1.tscn` 在 3D 空间中放置鬼剑士、萝莉安、莎兰、港口场景及光照。人物仍是原作逐帧图像；墙体、蓝门、拱门、窗框、地砖、中央摊位、码头、树干、木桶和系船构件为新建 3D 几何。船只、树冠和远景继续使用原图，不将这部分标作 3D 重建完成。

固定方向正交镜头，默认 1792×808 的 3D 视窗嵌在原有 960×540 逻辑界面中。F6 或画质按钮可切换 896×404／1792×808，镜头与场景布局不变。F4 在 R0 原图基准与 R1 混合场景之间切换，保留位置、朝向、动作帧、播放时间、暂停、下一段普攻和 R1 画质选择。顶部菜单补充八组原始姿势；F7 原地转向，F1 显示拖动选帧滑条。F1 同时显示一组前景遮挡／碰撞探针；测试石块平时隐藏，不属于原地图内容。

Space 或底部按钮启动实际跳跃，空中 X 可挥剑一次；起跳、上升、下降和落地共用 `source_jump.gd`。F4 也保留离地时钟、空中攻击状态与启动时的平移速度。

当前 R1 默认开启行走／奔跑下肢过渡：两种动作各在八张原图之间增加 16 张派生图，下肢 30 Hz，头部、上衣和武器仍为原图 10 Hz，两种动作的周期均为 800 ms。F5／右下“步态”可即时与原帧对照，F4 保留选择；R0 始终原图。攻击保留原始动画节奏。后文逐轮记录包含历史版本，当前运行和验收证据以候选 27 为准。

## 视觉迭代与技术选择

第一版纯色墙面和规则地砖过于干净，不能作为视觉通过依据。当前版本改为：

- 从 `westtile00` 原图测量曲墙轮廓，以固定视角的投影 UV 保留原画墙面、蓝门的磨损与石块细节。模型有厚度、独立门板与石框；侧面、厚度和背面是本次新建内容。投影贴图有固定视角的适用范围，不代表已获得完整建筑材质。
- 对原图中八块地砖做最近邻四边形校正，放到有薄厚与小倒角的 3D 砖面上；保存采样四边形、摘要和参数。砖面仍使用原画中的绘制痕迹，未用通用纯色方块替代。
- 船只使用透明表面；人物由 R0 中保留的可编辑图层，按原偏移和顺序合成为有脚底锚点的透明表面。原始分层和来源没有丢弃，派生关系见 `r1_derivative_manifest.json`。
- 人物保留原画颜色，使用原生深度测试；接触阴影与人物轮廓投影分别处理。原图中的武器和脚尖有少量像素超出逻辑脚底，着色器只沿视线调整这部分深度，避免它们被地面裁切，同时保留被高于地面的构件遮挡的能力。
- 地面位置、朝向、动作状态和表现偏移分别保存；本轮尚未执行 ANI 的攻击事件、伤害、取消或技能轨迹。

## 候选 06：跳跃、空中挥剑与连续演示

候选 05 的源、数据、脚本和报告已留在 `source_art/r1/checkpoints/candidate_05/`。港口模型和原始 PNG 本轮未改动。

重新从 95 PVF 读取 `swordman.chr`、`jump.ani` 与 `jumpattack.ani`，数据 CRC 和整个 PVF 的 SHA-256 均通过。CHR 的跳跃力为 430、跳跃速度为 95；跳跃 16 帧中，第 7、14 帧是 10,000 ms 保持帧，有限上升和下降段各为 500 ms。证据见 `r1_jump_source_reference.json`。

当前采用可调映射：将 430 映射为垂直原图像素／秒，以有限上升段 0.5 秒计算重力 860 像素／秒²；95 映射为空中平移速度，跑跳乘数沿用样片的 1.9。起跳准备 100 ms、空中 1 秒、落地 50 ms，默认全程 1.15 秒，顶点为 107.5 像素。原引擎的单位转换、重力实现与保持帧触发条件仍待验证；这些参数和阶段划分属于本次映射，未作为原引擎复原结论。

`source_jump.gd` 同时驱动两份场景。R0 的显示层向上移相同像素，R1 按 `height / (60 × cos(38°))` 换成世界竖直位移；顶点约 2.274 米，对应镜头投影下的 107.5 像素。接触阴影留在地面，尺寸由 1 缩至 0.7、透明度由 0.27 降至 0.12。CharacterBody3D 继续作为城镇导航体，地面逻辑点受既有行走区与碰撞阻挡约束；高度用于离地显示与动作状态。

空中 X 播放原始六帧 `jumpattack`，每跳一次，不消耗地面的下一段普攻；挥剑结束后回到当前上升／下降姿势。落地进入原跳跃末帧，再恢复自由操作。Esc 恢复自由控制时保留正在进行的飞行。顶部原始姿势菜单继续保留完整 10 秒保持帧；切换到原始预览会结束实际跳跃。

暂停会冻结高度和动作时钟；F3 在实际跳跃中推进 1/60 秒，在原始预览中推进一个 ANI 帧。F1 拖动选帧时保留离地高度。F4 往返保留时钟、空中攻击、当前帧、暂停和启动速度。R0 的地面移动同步改为物理帧更新，消除与 R1 更新频率的差异。

空格最初通过全局按下状态轮询，也会在选择菜单项后触发跳跃。现改由未被界面处理的按键事件启动，菜单的空格选择已实际复查；按钮仍可直接启动跳跃。菜单打开时隔离地面移动与攻击输入，既有飞行继续推进。

## 导出与导入注意事项

本轮遇到编辑器缓存仍保留旧模型的情况，工具返回“reimported”不能单独证明运行时已经换成新模型。当前流程在导出后执行完整 Godot CLI 导入，并从指定场景文件启动，再检查运行时节点和材质。实机检查包含这项核对。

停止播放后，可使用现有 NumPy／Pillow Python 运行：

```sh
/Users/mac/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 tools/r1/rebuild_r1.py
```

该命令先检查 `tools/r1/*.gd` 的语法，再重建生成的场景和模型；手动改过的 `.blend` 如与上次生成摘要不一致，会保留并停止重建，应将人工修改单独导出。场景的手工调整也应另存或同步回生成脚本。

实机检查入口为 Godot game-eval：

```gdscript
return await load("res://tools/r1/runtime_checks.gd").new().run(get_tree().current_scene)
```

它需要正在运行的 R1 图形场景，会短暂切换场景、移动人物、截图并生成结果，完成后恢复到正常可操作状态。

摊位补充入口为 `tools/r1/stall_checks.gd`，第二参数可指定候选版本，默认 `"R1/11"`，结果与截图按版本保存。候选 03 的画质入口为 `tools/r1/quality_checks.gd`；其输出名固定为 03，重跑前应保留历史结果。同一游戏进程中修改 QA 脚本后，需要读取磁盘源码并 `reload()`，不能把缓存中的旧脚本结果当作新检查。报告保存实际执行脚本的 SHA-256，可与对应版本文件核对。

通用全帧截图入口为 `tools/r1/capture_full_frame.gd` 的 `run(current_scene,"r1_14")`，第二参数是版本文件名前缀。它创建独立视窗，截图后恢复主视窗、人物状态和画质，并关闭文件句柄后再返回。

完整姿势检查超过 Godot MCP 单次 game-eval 的 8 秒回复上限时，超时不会取消已经等待中的 GDScript 协程。应把 `tools/r1/pose_check_job.gd` 实例挂在 `/root/R1PoseChecksRun`，调用 `start(current_scene)` 后只轮询 `snapshot()`，直到活跃节点报告 `status == "complete"`，再移除节点。检查期间不并行移动或切换运行场景。本轮终态保存在 `r1_14_pose_job.json`。同一包装器支持第二参数 `"res://tools/r1/jump_checks.gd"`，对应跳跃检查；采用单独节点名 `/root/R1JumpChecksRun`。

离线来源复核入口为 `tools/r1/verify_actor_sources.py --candidate R1/14`，使用已有 Pillow Python；它校验原图摘要、ANI CRC、RGBA 合成和导入配置。动作参考导出入口为 `tools/dnf_client_analysis/export_motion_reference.py`，会读取客户端数据并更新证据，保留已存在的运行参数；`--write-defaults` 才会覆盖现有调参。

30 秒观察使用 `tools/r1/render_observation.gd` 实例，挂到运行树后调用 `start(current_scene)`，再轮询实例的 `snapshot()`，直到 `status == "complete"`；`cancel(reason)` 会恢复主场景。报告文件存在不能代替活跃节点状态。观察完成后应移除该 QA 节点。
