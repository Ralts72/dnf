# 素材生产方案

更新日期：2026年10月26日  
状态：Demo临时路线与A/B/C生产方式已确认；正式来源、完整规格和工具链待验证。

## 当前素材策略

Demo阶段暂用怪猎模型与可用动作，优先验证本作玩法。辟兽已完成Blender单样本验证，人物角色模型后续再获取与验证；不因此照搬原作整套AI、职业、数值与装备系统。正式素材生产路线后续再定。

临时模型与骨骼名称通过独立映射接入动作、挂点和可命中部位，玩法不直接依赖原作文件名。工具许可与游戏资产使用范围分别记录，后续保留原创或可发布素材的替换入口。实际提取范围、文件大小和未验证项见[怪猎资产验证](../04-原型验证/怪猎资产验证.md)。

视觉目标：写实比例、风格化表现；固定观察方向，装备可换装，巨兽有部位承伤。用户通过参考选择、预览与试玩反馈参与。

## 三类素材生产方式

素材生产总体分为以下三类。分类依据是每一步的生产方式，一项素材可以连续使用多类方式。

| 类别 | 定义 | 典型用途 |
| --- | --- | --- |
| A AI直接生成 | 调用生成式模型，直接取得图像、视频、语音、声音、音乐、模型或动作候选 | 生图、配音、视频、生成式建模、动作片段 |
| B AI使用软件生产 | AI通过软件操作、脚本、节点与参数构造素材 | Blender建模、绑定、关键帧动画、材质烘焙；Godot粒子、着色器和UI制作 |
| C 对已有素材后处理 | 以AI输出、现成资产包或开源素材库为输入，完成提取、修改、适配与整合 | 视频抽帧、抠像、打图集、模型清理、动画重定向与修改、音频剪辑 |

B与C可能使用同一个软件：在Blender中新建规则型武器主要属于B，修改已有模型或动画主要属于C。通过生成式服务直接得到3D模型属于A，之后可以继续进入B和C。类别不由文件格式决定。

### 组合生产链

- 概念图：A生成 → C筛选、裁切与整理。
- 武器：A设计参考 → B在Blender制作 → C整理、导出与适配。
- 特效：A生成纹理或视频 → C处理纹理与序列帧 → B组装引擎特效。
- 配音：A生成语音 → C校对读音、剪辑、统一音量并关联台词。
- 骨骼动画：C修改素材库动作 → B补充需要的新关键帧或过渡 → C导出与引擎适配。

### 视频转序列帧

A生成参考图或视频 → C选择有效片段、调整时间与稳定画面 → 按目标时序抽帧 → 抠像及透明边缘处理 → 统一尺寸、锚点和帧序 → 检查循环接缝与帧间一致性 → 打包图集并建立播放配置 → B在Godot组装显示或特效场景。

交付保留原始视频、处理参数、透明帧或图集、帧率与播放信息、锚点和预览。检查主体比例漂移、背景残留、闪烁和循环跳变。实际透明度与时序质量以处理结果为准。

这是一条可选的2D素材生产路线，可用于特效、UI动效、预渲染展示或明确采用2D表现的对象。它不自动改变当前角色与场景的3D规划。

### 素材库动作修改

选择来源明确的骨骼动画 → C重定向到统一骨架 → 调整参考姿势、比例、方向和握持 → 修改关键帧、节奏、轨迹与位移 → 按需要由B补充缺失动作和过渡 → C导出并配置动作事件 → 引擎试玩验收。

交付原始动作、修改后的骨骼动画、骨架映射、变化说明、位移约定、动作事件与预览。普通走跑与核心剑术可以采用不同的修改深度。

## 推荐生产方式

以A、B、C组合选择具体路线：兼容的现成人形、骨架、动画与模块化服装作为C的输入基础；A提供概念、外形、声音等候选；B与C完成制作、适配、表现组装与验收。

对关键战斗动作、衣甲混搭和怪物变形，单独验证实际质量。可用性由导入后的动作、接触、换装和镜头效果判断。

## 需要的素材类型

| 武器与防具 | 实际穿戴、混搭及升级外观 | 武器可模块化制作，防具使用适配同一基底的分件 |

| 特效 | 剑光、命中、弹反、法术与环境反应 | 引擎粒子、轨迹、着色器配合特效纹理 |

| 声音与音乐 | 挥剑、命中、脚步、环境、界面和地区氛围 | 现成音效整理混合，音乐按后续题材制作或选择 |
| 技术交接数据 | 挂点、部位、碰撞、材质分类、动作事件 | 随模型和动作一起建立配置与检查入口 |

## 分类型生产流程

以下是建议的默认生产路线。每类标注主要生产方式，实际步骤按素材情况组合。每项交付运行时文件、来源与规格、预览和检查结果，具体服务与资产包尚未选定。

### 视觉参考与概念图

主要方式：A → C。

AI生成造型候选 → 用户选定轮廓与气质 → 基于同一参考迭代配色、服装与细节 → 整理正面、侧面、背面及尺寸说明。

交付参考图与简短风格规范。多视图作为制作参考，实际模型仍需统一尺寸和结构。验收重点是辨识度、题材一致性与当前镜头下的轮廓。

### 人体基础模型

主要方式：C复用和适配基底；需要新增造型时结合A参考与B制作。

筛选比例与拓扑合适的已绑定基底 → Blender统一单位、朝向和参考姿势 → 调整材质与必要比例 → 导出Godot预览。

交付基础身体模型、材质、骨架信息与可运行预览。优先检查肩肘膝等关节变形和与衣甲模板的兼容。

### 头部 头发与外观预设

主要方式：C组合已有部件，B补充部件或参数化预设，A提供设计参考。

使用同一体系的头型、发型与面部基础 → 通过部件替换、材质与配色形成预设 → 确有需要时增加形态变化 → 在动作与装备中检查。

交付头部或发型部件及预设配置。脸部复杂表情、身形滑杆等范围另定，第一轮以可稳定复用的外观预设验证流程。

### 骨架与蒙皮

主要方式：C复用与适配骨架，B建立或补充绑定及权重。

沿用已经验证的基础骨架 → 新部件适配参考姿势 → 迁移或建立蒙皮权重 → 固定动作组检查变形 → 修正后导出。

模型是外形，骨架定义关节，蒙皮权重决定外形如何跟随关节。交付包含绑定模型、骨架映射、挂点与变形预览。

### 分部位防具

主要方式：A设计参考 → B制作新部件或C修改现有部件 → C适配、检查与导出。

优先采用相容的模块化服装 → 按装备槽位整理分件 → 新造型在同一身体模板上制作或适配 → 处理蒙皮、身体遮挡与材质 → 混搭后测试。

头盔等刚性部件可使用骨骼挂点；衣服、裤子等变形部件使用蒙皮。披风、长裙等优先选带对应绑定的模板。交付独立分件、绑定、覆盖关系与组合预览，抬手、屈膝和挥剑时检查穿插。

### 武器与刚性饰物

主要方式：A参考 → B建模 → C整理导出；生成式模型也可采用A → C。

AI生成外形参考 → 规则型形体用Blender脚本与模块制作，复杂装饰可用现成件或AI建模候选 → 整理网格与材质 → 设置握持原点与挂点 → 引擎测试。

交付模型、材质、握持规格与装备预览。剑刃、护手和剑柄等可复用组件，并通过比例、轮廓和材质形成系列。实际长度和握持位置与攻击范围共同验证。

### 怪物模型与绑定

主要方式：C修改完整基底；原创方案结合A外形候选、B制作与C适配。

首个样本优先选择自带骨架与动作的怪物 → 调整外观与材质 → 配置部位、挂点和受击体 → 用自身动作验证。

原创怪物可走概念图 → 现成基底改造或AI模型候选 → 网格整理 → 对应体型绑定 → 动作适配。外形、绑定与动作各自验收，双足、四足、飞行和多肢采用适合的流程。

交付模型、骨架、动作、部位配置及预览。AI绑定工具的适用体型与动画库支持按实际入口验证。[Meshy绑定范围](https://docs.meshy.ai/en/webapp/guides/3d-model/rigging)

### 通用骨骼动画

主要方式：C修改素材库动作；AI生成片段采用A → C，缺失内容由B补充。

选择兼容动画库 → 重定向到统一骨架 → 统一动作方向、尺寸与命名 → 调整脚底、步幅、握持与过渡 → 引擎验证。

适用于待机、走跑、情境跨越、普通受击、死亡和通用互动。交付动画库、骨架映射与测试入口；少量招式跃起按具体招式补充，初版不要求通用自由跳跃。AI文字生成动作可补充候选；例如Meshy提供独立运动片段生成与后续重定向流程，质量需实测。[官方动作生成说明](https://docs.meshy.ai/en/api/text-to-motion)

本轮动作方案还需要区分自由转身移动、瞄准施放时的后撤与侧移，以及近战停步或踏前动作。动作结束后的过渡和是否需要上下半身分层，结合具体招式验证。详见[移动朝向与动作权限方案](../01-玩法规则/动作权限.md)。

### 核心战斗动画

主要方式：C修改现有骨骼动作 + B补充关键姿态与过渡；A视频或动作片段作为候选输入。

先定义招式用途与动作阶段 → 寻找接近的动作或生成草稿 → 在骨架上调整关键姿态、节奏与武器轨迹 → 配置位移、窗口和派生 → 在固定敌人与镜头下试玩迭代。

交付动画、动作配置、轨迹与阶段预览。剑术动作、防御反击和Boss招式使用此流程。动作参考视频可帮助确定表现，进入游戏的骨骼轨道与规则仍需单独制作和检查。

### 地形与建筑

主要方式：B在软件中构建关卡和模块，C整合现成场景素材，A提供视觉参考。

先确定路线、战斗空间与高低差 → 用简单几何验证通行和镜头 → 用地形工具与模块套件铺设 → 补材质、植被、灯光和地标 → 检查碰撞与导航。

交付地区场景、模块、碰撞、导航与预览。墙、门、窗、台阶、桥等按统一尺寸组合；标志建筑单独设计。场景美化沿用已经验证的路线。

### 道具与植被

主要方式：B规则型制作或C资源库改造；特色模型候选采用A → C。

箱、桶、门、火盆等优先现成套件或脚本化建模；特色摆件可用AI建模候选。树木、灌木和草优先统一植物库，再做比例、材质与摆放变体。

流程为筛选或生成 → 整理 → 材质统一 → 简化碰撞 → 批量布置与性能检查。交付模型、材质、碰撞与必要交互配置。动态植被与物理范围按后续需求确定。

### 材质与贴图

主要方式：C整理现成贴图或A → C生成与处理纹理，B组装材质与烘焙数据。

先建立石、木、金属、皮革和布料等共用材质 → 使用完整数据贴图或程序纹理 → AI补充图案与表面候选 → 在统一光照下调整色彩、粗糙度与细节。

交付基础色、法线、粗糙度等实际需要的贴图和引擎材质。AI生成的外观图需要继续转成适合材质系统的数据；数据贴图通过对应生成、烘焙与预览流程验证。Poly Haven可作为纹理与HDRI来源候选。[官方资产说明](https://polyhaven.com/license)

### 天空 光照与天气表现

主要方式：B配置天空、光照与天气系统，C适配HDRI等已有素材；A可提供纹理候选。

选择HDRI或程序天空 → 调整环境光、主光、色调与雾 → 配置雨雪粒子、风和湿润表现 → 将表现参数与实际环境状态对应。

交付环境配置、天气效果、参数与预览。天气的可见表现与温湿度模拟分别制作，再通过同一天气状态连接。

### 战斗与环境特效

主要方式：A生成或C取得纹理、视频等输入 → C处理序列帧与图集 → B组装特效。

确定效果用途和发生阶段 → AI或现成素材提供烟、火、噪声、符号等纹理 → 用Godot粒子、轨迹、网格与着色器组合 → 配置颜色、持续时间和挂点 → 战斗中调节辨识度。

交付可复用特效场景、材质和参数。燃烧、烟雾、火花与魔法等可使用引擎粒子系统。[官方粒子说明](https://docs.godotengine.org/en/stable/tutorials/3d/particles/index.html)

### UI布局 边框与字体

主要方式：B制作交互控件，A生成装饰素材，C处理图形、字体与按键提示。

先制作可交互布局 → 采用统一主题与现成字体 → AI补充边框和背景纹理 → 调整缩放、中文排版与手柄焦点 → 连接真实数据。

交付Control场景、主题、字体与图形资源。文字、按钮和布局由界面控件实现，可拉伸装饰与背景分开处理。按键提示使用现成图形库并由输入绑定配置选择。[Kenney按键提示](https://kenney.nl/assets/input-prompts)

### 装备 技能与材料图标

主要方式：C基于实际模型渲染与整理图标；抽象图标采用A → C。

装备优先使用实际3D模型 → 固定镜头、灯光和背景自动渲染 → 统一裁切与尺寸。技能和抽象材料可由AI按固定模板生成 → 检查小尺寸辨识度 → 导出。

交付图标与对应内容ID。背包物品、模型和图鉴通过ID关联，保持轮廓、配色与物品身份一致。

### 音效

主要方式：A生成或C取得现成声音 → C剪辑、叠层与混音；B配置引擎事件。

选取现成录音或生成候选 → 剪辑、叠层、均衡与音量调整 → 为不同材料和事件准备适量变体 → 绑定动作事件与空间位置 → 实机混音。

交付声音文件、事件映射与播放参数。挥空、金属接触、肉体命中、脚步和界面等分别组织。角色动画与音效事件一起检查。

### 音乐与配音

主要方式：A生成音乐或语音 → C筛选、校对、剪辑与混音；现成音乐以C为主。

音乐按地区气氛、探索与战斗状态确定主题 → 从现成作品或AI生成段落中选择 → 剪辑循环点、过渡与音量 → 场景内试听。

若采用配音，先固定角色音色、台词ID与专名读音 → 生成候选 → 校对发音、情绪与时长 → 批量导出并关联对白。是否全程配音、音乐数量与具体服务另定。

交付音乐或语音文件、循环与过渡信息、对白映射和试听入口。

再战短语音素材需包含死亡后重返或重试的条件台词，并在对白映射中记录说话者与触发条件；具体数量和重复播放策略按[补给与复归](../01-玩法规则/补给与复归.md#死亡再战的特殊语音)的设计配置，不因新增短语音而扩大为全程配音承诺。

### 技术数据与内容配置

主要方式：B制作规则、配置与校验工具，C从已有资产提取并校准交接数据。

根据稳定内容ID整理挂点、碰撞、部位、材料分类与动作事件 → 为装备、技能、配方等生成配置草案 → 校验引用和规则 → 试验场验证。

交付Resource配置或约定的数据文件。几何与骨骼可以提供初始尺寸，实际受击范围和动作窗口按玩法校准。数值草案通过战斗与成长循环验证。


概念图、绑定完成的模型、完整战斗动作是不同阶段的产物。每一步的验收条件分别定义。

## 人形与分部位换装

先验证一个标准人形基底。玩家和普通人形敌人尽量复用该骨架，通过衣甲、头发、武器、配色与少量造型差异形成角色。

为防具确定统一的分件规则和覆盖关系，衣甲沿用共同骨架与蒙皮规范。穿戴时检查身体遮挡、关节变形、装备之间的穿插和武器握持。

第一轮用一个体型验证技术流程，正式角色创建支持哪些体型与外观选项仍待设计确认。

Quaternius提供相互配套的基础人形、模块化幻想服装与人形动画。其服装页明确标注与基础角色及动画库兼容，可以作为技术样本候选。[基础人形](https://quaternius.com/packs/universalbasecharacters.html)、[模块化幻想服装](https://quaternius.com/packs/modularcharacteroutfitsfantasy.html)、[动画库](https://quaternius.com/packs/universalanimationlibrary.html)

这些候选用于验证骨架、换装和动作流程。正式素材继续以写实比例、风格化的统一视觉基准筛选。具体下载版本的文件组成和使用条件随资产来源记录。

## 动画优先建立一套可用动作

剑士的首批动作候选：

- 待机、行走与奔跑。
- 情境跨越及少量招式离地／落地，按具体需要拆分阶段；不批量制作通用跳跃与完整空中连段。
- 基础闪避、格挡及防御反馈。
- 少量轻击、重击及派生动作。
- 普通受击、倒地或死亡反馈。
- 握持武器与必要的动作过渡。

这不是最终动作数量。先保证移动、攻击、防御与受击形成可玩的循环，再补足独特招式。

现成动画先重定向到统一骨架。Godot的人形重定向需要考虑骨骼映射、参考姿势与变换关系，名称一致本身不足以保证复用。[官方骨架重定向说明](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/retargeting_3d_skeletons.html)

动画导入后重点检查：握剑位置、脚底接触、移动与步幅、动作衔接、武器轨迹和受击反馈。攻击窗口、取消与资源规则由动作系统配置，与动画一起验证。

原地动画与根运动的选择属于后续技术验证。原型可以先验证由逻辑驱动位移的方案，重要攻击根据表现需要继续评估。

## 怪物需要独立考虑身体结构

大型怪物除了外形，还需要移动、攻击、转身、受击、失衡等动作，以及对应部位的挂接和检测。

首个验证怪物可优先选择已有骨架与动作的模型，通过其自身动作测试体型、距离、部位与防御规则。具体物种和最终造型仍待设计。

四足、飞行或多肢结构分别选择适合的骨架和动画。AI生成的怪物外形可以提供候选，但其变形与动作仍需要独立验收。

Mixamo的官方FAQ说明其自动绑定与动画库面向双足人形，同时列有中国地区账户限制，因此不作为本项目必经步骤。[Adobe官方FAQ](https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html)

## 场景与静态资产

围绕少量可组合模块建立试验场，再扩展到地区：

- 地面、墙体、台阶、坡道、桥等结构。
- 树木、岩石、木箱、火盆、门等物体。
- 共用石、木、金属和布料材质。
- 能在当前镜头下识别的特色轮廓与少量标志物。

规则型物体可以通过Blender脚本生成与修改；已有场景套件提供基础组件；AI生成适合补充独特道具与外形候选。所有来源按比例、材质与色彩规范统一。

Kenney的Fantasy Town Kit可作为模块化场景验证候选，其官网提供3D套件与明确的资源信息。正式视觉质量仍需在既定镜头中比较。[场景套件](https://kenney.nl/assets/fantasy-town-kit)

AI建模服务如Meshy可以作为候选生成工具。其Web工具文档介绍了人形与四足绑定，并说明自定义骨架及动画库有各自适用范围；具体自动化入口与产物需要实测，工具接入尚未进行。[Meshy绑定说明](https://docs.meshy.ai/en/webapp/guides/3d-model/rigging)

## 特效 界面与声音

剑光、命中闪光、弹反火花与元素反馈优先形成少量统一效果。引擎负责粒子、轨迹、着色器和时序，AI或现成素材提供纹理候选。

界面采用统一的边框、字体、颜色与图标规范。装备图标优先从实际模型自动渲染，使物品图标与穿戴外观对应。技能图标与概念图可采用统一参考生成后再检查辨识度。

声音先覆盖挥剑、命中不同材料、脚步、防御与界面反馈。现成音效可以剪辑混合并调整；音乐与配音等题材和演出范围明确后再安排。Kenney的Impact Sounds是可检查的初期候选之一。[音效来源](https://kenney.nl/assets/impact-sounds)

## 每个素材包的交付

建议交付：

- 素材ID、A/B/C生产链与每步输入输出。
- 原始工程与来源记录。
- 生成提示、参考、软件工程、处理参数与版本信息，按适用步骤保留。
- 运行时模型、材质、贴图及动画。
- 比例、轴向、骨架版本与命名信息。
- 必要的武器挂点、部位、碰撞和材质分类配置。
- 引擎预览入口与截图或动作预览。
- 已检查项目与待修复问题。

用户主要比较外观、动作与试玩效果。技术工序由AI协助处理；达不到要求的资产明确标记，再调整来源、基底或处理步骤。

## 建议的第一批验证素材

以下数量仅为讨论中的建议：

- 一个统一的人形基底，供玩家与人形敌人验证。
- 两组可替换的衣甲部件，用于验证混搭。
- 一把剑及其握持挂点。
- 一套最小移动、攻击、防御和受击动作。
- 一个自带绑定与动作的大型怪物样本。
- 一小组地面、台阶、墙和可交互物体。
- 几种命中、防御与基础环境反馈。
- 最小HUD、物品图标与核心音效。

先用这组资产跑通“导入、动作、换装、部位、镜头与反馈”，再决定正式角色、怪物和地区的生产路线。
