# AI协作工作流

更新日期：2026年10月26日  
状态：已确认协作方向；设计讨论和开发授权分别处理。

## 基本循环

设计目标 → 任务卡 → 实现与自测 → 可玩交付 → 用户试玩反馈 → 修正与记录。

在授权的任务范围内，AI完成常规、可逆的实现和调试。涉及重要设计取舍、范围变化或验收判断时，把具体问题与影响交给用户决定。

## 设计讨论的节奏

- 用户要求加快讨论进度：每轮可集中提出2～4个相对独立、影响明确的问题，给出简短选项与推荐，避免反复确认已确定内容。
- 相互耦合的关键问题分轮推进：先确定上游机制，再据答案讨论相关武器、资源、成长或内容范围，不同时把互相依赖的结论交给用户选择。
- 常规、可逆的技术实现选择在后续具体授权任务中处理，不把每个参数都变成设计问卷；测试参数和最终规则分别记录。
- 批量提问不表示扩大开发授权；当前仍为设计整理，未获新指令前不创建工程或恢复复刻。

## 单个任务的格式

任务应形成可运行的小闭环，让用户能进入场景直接观察变化。

建议任务卡包含：

- 目标：完成后玩家能够观察到什么行为。
- 场景与输入：启动入口、角色、敌人、装备和操作条件。
- 范围：本轮涉及的功能及必要边界。
- 行为规则：已经明确的机制、配置与参数。
- 验收：能够复现的成功条件与边界情况。
- 交付：运行入口、复现步骤、实际验证结果与已知问题。

示例为人形部位命中：

- 固定试验场、角色、敌人和装备。
- 接触裸露头部与躯干时得到对应部位结果。
- 人形只允许锁定主体。
- 锁定不改变攻击的实际可达范围。
- 重复接触按本轮明确的结算规则处理。
- 部位伤害、防御和调试反馈能够对应起来。

这是任务格式示例，具体倍数、重复命中规则与时间窗口仍需设计。

## 素材交接规范

生产方式统一分为A（AI直接生成）、B（AI使用软件生产）、C（对AI输出或已有素材后处理）。一项资产按步骤记录组合生产链。定义与分类型路线见[素材生产方案](素材生产方案.md)。

素材也通过明确的规格与产物交接：

- 素材ID、生产类别与组合步骤。
- 原始输入、生成参考、软件工程和后处理参数及版本。
- 人物比例、单位、朝向与原点。
- 骨架版本、骨骼名称及装备挂点。
- 动画命名、参考姿势与动作位移处理。
- 模型、材质、贴图及导出物的组织。
- 引擎内预览、动作检查与换装检查入口。

3D角色流程为：概念与造型 → 模型 → 绑定 → 动画 → 导出 → 引擎预览。序列帧可以采用生成视频 → 后处理抽帧与透明边缘 → 图集与播放配置 → 引擎预览；骨骼动画可以采用素材库动作 → 修改和重定向 → 补充与导出 → 引擎预览。每一步保留对应产物，并尽量复用已经验证的规范。

AI协助制作的素材同样需要在实际镜头和动作中检查。具体素材来源、工具与生产方案另行讨论确认。

用户目前没有美术技能，生产流程需要使用户主要通过参考选择、预览比较和试玩反馈参与，而非把建模、UV、绑定等技术处理作为前置要求。

## 验证与完成状态

| 类别 | 关注内容 |
| --- | --- |
| 规则验证 | 伤害、肉质、资源、升级、配置引用与存档结果 |
| 场景运行 | 启动、加载、切区、暂停、输入与画面 |
| 体验试玩 | 动作分量、距离判断、防御与走位价值、重复挑战感受 |

AI执行适用的检查，依据反馈修复后复验。测试通过只表明对应检查条件成立，体验满意由用户实际试玩判断。[官方验证循环示例](https://developers.openai.com/cookbook/examples/codex/build_iterative_repair_loops_with_codex)

进度记录区分：

- 已实现但尚未运行。
- 已完成对应运行或规则验证。
- 已通过用户体验验收。
- 已知问题、未覆盖情况与下一步。

本地场景运行记录、截图、录屏或构建结果只在实际获得后作为证据。无需为每项低影响修改生成大量重复报告。

## 试玩反馈

用户提供场景、操作、观察到的现象和期望。能够定位时补充录屏时间点。

例如：锁定敌人后，重击已挥出仍大幅追踪敌人；期望准备阶段可以调整，挥出后保持方向。

用户不需要指定技术修复方法。现象难以归因时，保持角色、敌人、装备和镜头条件稳定，逐项比较方向、位移、时序和表现变化。

## 迭代与版本

每轮围绕一个可玩的目标推进。完成小闭环后按版本管理约定保留可恢复检查点，方便比较与回退。版本提交、发布等具体操作按当次授权执行。

用户每周约15小时优先用于：

- 确认体验目标与取舍。
- 选择参考和素材方向。
- 试玩结果并提供具体反馈。
- 决定保留、调整与延后内容。

常规实现、适用验证、调试与状态维护由AI协助完成。原型结果决定后续内容量与迭代安排。
